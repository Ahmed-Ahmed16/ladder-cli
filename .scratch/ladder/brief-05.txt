<command>
`ladder pr wait-review <n> [--bot LOGIN] [--timeout-mins N]`.
- Reviewers: `--bot` (may be given more than once) replaces the config list; otherwise [review] wait_for. Empty or missing -> at once: `no reviewer set: add [review] wait_for = ["login"] to ladder.toml or pass --bot`, exit 1. No sleeping at all in that case.
- --timeout-mins: whole number >= 1, default 20.
- Each poll: head commit with `gh pr view <n> --json headRefOid -q .headRefOid`; reviews with `gh api repos/{owner}/{repo}/pulls/<n>/reviews --paginate`. A login counts as done when it has a review whose commit_id equals the head commit (any state except PENDING). Login compare is case insensitive.
- Print a status line only when the state changes: `<short sha>: waiting for <login, login>` or `<short sha>: done: <login> (<STATE>), ...`. When the head commit changes between polls, say so and keep waiting for the new commit.
- All done -> exit 0 with the final done line. Timeout -> `ladder: timed out after N min; still waiting for <logins> on <short sha>`, exit 1.
- Poll every 30 s. Time and sleep come through a seam (for example main gets `clock` and `sleep` parameters with real defaults) so tests run instantly and assert the sleeps requested.
- Parse the reviews JSON in a pure function; bad JSON or a missing field gives a plain error. --paginate can return several JSON arrays back to back; handle that (concatenated arrays like `[...][...]`).
</command>
