<production_findings>
1. cli.main() takes 8 parameters and is a long if/elif chain over jobs; `load_config(os.getcwd())` repeats 4 times. Split each job into its own small function and dispatch through a table from job name to function. Group the injected seams (runner, out, err, load_config, home, clock, sleep) into 1 small object (for example a frozen dataclass `Context`) so main has at most 4 parameters. Keep `run()` as the real entry point. Update the tests' calls to main accordingly, without weakening any assertion.
2. Dead code: remove `NotImplementedError` from the except in cli config_check (the parser stub is gone); remove the unreachable try/except ValueError in timeout_minutes.
3. The core job list lives in 3 places: config.CORE_JOBS, cli.CORE_ABOUT, and the argparse help strings, and they already disagree (doctor's argparse help omits ladder.toml). Keep 1 source: CORE_JOBS stays in config (the parser needs it for clash checks); the about text lives in 1 table that both `ladder list` and the argparse help strings read. After the fix, doctor's help and list text are the same string.
4. review.ReviewWait.wait() is about 35 lines doing fetch, parse, compare, print and timeout. Extract the "which reviewers are done on this head" step into a pure function and the status line building into another, so wait() reads as the loop only. Keep all output identical.
5. process.path_program(): the check that returns None when the found program's folder equals the current folder and is not an allowed PATH folder can never fire, because only absolute PATH folders are searched. A mutation run deleting it left all tests green. Delete it (and the `allowed` set). Keep the PATH filtering that does the real work, and keep its existing tests.
</production_findings>
